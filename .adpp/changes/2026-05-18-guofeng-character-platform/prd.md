## 1. 背景与目标

### 1.1 背景

当前面向国风角色创作的用户群体，包括女性用户、小说作者、汉服圈用户和自媒体创作者，普遍有“快速生成高质量国风角色形象”的需求，但现有通用 AI 绘图产品在风格垂直度、角色表达一致性和国风语义理解上不足，难以直接满足 OC、梦女、人设展示、封面角色和国风写真的高频场景。

因此需要建设一个聚焦“国风角色生成”的垂直型 AI Web 平台，降低用户从描述想法到拿到可下载作品的门槛，并通过登录、积分和分享机制形成基础留存与变现闭环。

### 1.2 目标

- 提供一个面向女性向国风 OC、梦女、人设创作场景的 Web 端 AI 生成平台
- 支持用户完成一次完整的“登录 -> 输入描述 -> 选择风格 -> 生成 -> 查看 -> 下载”流程
- 提供国风风格模板与 Prompt 增强能力，提升角色生成质量与风格一致性
- 提供基础积分体系，支撑免费试用与后续付费转化
- 提供用户作品页与分享能力，支持内容沉淀和自然裂变
- 形成“生成 -> 分享 -> 回流 -> 再生成”的核心增长闭环

### 1.3 产品定位

本产品定位为：

**专注女性向国风 OC、梦女与角色幻想表达的 AI 生成平台**

核心不是做“通用 AI 绘图工具”，而是提供更适合小白用户和女性向角色创作场景的情绪化、模板化、低门槛生成体验。

### 1.4 产品差异化

| 维度 | 通用 AI 绘图产品 | 本产品 |
|---|---|---|
| Prompt 门槛 | 需要用户自己会写复杂 Prompt | 提供模板、风格和灵感引导，小白也能直接生成 |
| 风格范围 | 风格杂、泛化强 | 聚焦国风、女性向、角色幻想表达 |
| 国风理解 | 对汉服、朝代、东方审美理解有限 | 内置国风语义、朝代风格、服饰词库 |
| 女性向表达 | 缺少梦女、OC、人设场景优化 | 专门优化梦女、OC、头像、人设卡、封面等场景 |
| 增长机制 | 多数偏工具使用后即结束 | 内置分享、回流、新用户激励和模板传播机制 |

### 1.5 非目标（Out of Scope）

- 本期不要求实现复杂高级参数编辑能力，高级参数仅保留后续扩展位
- 本期不要求支持多端原生 App，仅聚焦 Web 应用
- 本期不要求实现复杂社区内容流、公开画廊或评论互动
- 本期不要求支持多模型自由切换或专业工作流级图像编辑
- 本期暂不细化高清生成、超精细生成背后的算法差异与调度策略

## 3. 核心增长闭环

### 3.1 闭环定义

产品核心闭环不是“生成 -> 下载”结束，而是：

```text
生成角色
-> 自动生成分享素材
-> 分享到小红书 / 微信等渠道
-> 新用户点击进入首页
-> 获得新手免费次数
-> 完成首次生成
-> 沉淀作品并继续分享
```

### 3.2 闭环目标

- 让生成结果具备天然可分享性
- 让分享内容能够清晰传达产品价值
- 让被分享带来的新用户能低门槛完成首次生成
- 通过免费次数、模板和案例内容提高回流与再生成

## 4. 用户生命周期设计

| 阶段 | 目标 | 核心动作 |
|---|---|---|
| 游客 | 看到案例 | 浏览首页、风格区、案例区、点击立即生成 |
| 注册用户 | 完成首次生成 | 登录、获得免费积分、选择模板、提交生成 |
| 活跃用户 | 持续生成 | 使用多风格、多模板、查看作品、再次生成 |
| 付费用户 | 充值 | 积分不足时充值，解锁更高质量与更多玩法 |
| 核心用户 | 分享传播 | 分享作品、使用热门模板、带来新用户回流 |

## 5. 核心指标体系

### 5.1 北极星指标

- `7日生成留存率`

### 5.2 关键指标

| 指标 | 目标 |
|---|---|
| 首页转生成率 | `>20%` |
| 生成成功率 | `>95%` |
| 登录转化率 | `>40%` |
| 首充转化率 | `>5%` |
| 分享率 | `>10%` |

### 5.3 指标说明

- 首页转生成率：进入首页的用户中，点击并完成提交生成的比例
- 生成成功率：进入生成任务后成功返回结果的比例
- 登录转化率：点击生成的游客中完成登录的比例
- 首充转化率：获得免费次数后的用户中完成首次充值的比例
- 分享率：生成成功用户中触发分享的比例

## 6. 功能需求

### 6.1 角色生成首页

**描述**: 提供国风角色生成的核心工作台，同时承担首页转化职责，让用户快速理解平台价值并进入生成流程。

**交互流程**:
1. 用户进入首页
2. 系统通过首页首屏向用户明确传达“这是一个 AI 国风角色生成器”
3. 系统展示 Banner、风格展示区、示例角色区、Prompt 输入框和生成按钮
4. 用户输入角色描述并选择目标风格
5. 用户点击“立即生成”
6. 系统校验登录状态和积分是否满足条件
7. 未登录用户在首页浏览阶段不受限制，但在正式发起生成前需完成登录
8. 校验通过后进入生成流程

**数据需求**:
- 用户原始 Prompt
- 所选风格
- 生成规格
- 登录态信息
- 当前剩余积分

### 6.2 首页信息架构

**描述**: 首页应在用户首次访问时快速建立产品认知，并用可视化案例引导进入生成。

**页面目标**:
- 让用户快速理解“这是一个 AI 国风角色生成器”
- 让用户感知支持的主要国风风格
- 让用户看到生成效果示例，提升点击“立即生成”的意愿
- 支持未登录用户先浏览首页内容，再决定是否登录生成

**页面模块**:

#### Banner

- 核心文案：`输入一句描述，生成你的专属国风角色`
- 核心按钮：`立即生成`

#### 风格展示区

- 展示盛唐风
- 展示汉代风
- 展示仙侠风
- 展示新中式

#### 示例角色区

- 展示用户生成案例
- 用于帮助用户理解平台可生成的角色质量与风格范围

#### 情绪化模板入口

- 展示更具幻想身份感的模板文案，例如：
  - 清冷月下女剑仙
  - 长安贵族千金
  - 病娇红衣妖姬
  - 白狐仙灵少女

**设计原则**:
- 模板不只表达“功能”，还要表达“幻想身份”
- 强调情绪价值，而不是仅强调出图能力

**交互流程**:
1. 用户进入首页首屏
2. 系统展示 Banner 主文案和“立即生成”按钮
3. 用户浏览风格展示区、示例角色区和情绪化模板入口
4. 未登录用户可直接浏览首页全部公开内容
5. 用户点击“立即生成”后进入生成工作台或直接定位至生成区
6. 如用户尚未登录，系统在实际提交生成请求前触发登录流程

**数据需求**:
- Banner 文案
- 风格展示项
- 示例角色图片与说明
- 情绪化模板卡片
- 首页按钮点击数据

### 6.3 Prompt 输入与示例提示

**描述**: 提供自然语言输入框，并展示示例输入帮助用户快速上手。

**新手引导目标**:
- 降低用户“不知道怎么描述”的心理门槛
- 提高首页到首次生成的转化率

**引导能力**:
- 自动推荐示例 Prompt
- 一键灵感按钮
- 随机生成 Prompt

**推荐示例**:
- `盛唐时期华贵贵族女子`
- `仙侠白衣少女`
- `新中式冷艳女性`

**交互流程**:
1. 用户看到输入框及示例文案
2. 用户输入如“盛唐时期丰腴贵族女子，金色步摇，红色齐胸襦裙，端庄华贵”
3. 系统记录输入内容，供后续 Prompt 组装使用
4. 用户若无思路，可点击“一键灵感”获取随机 Prompt

**数据需求**:
- Prompt 文本
- 输入时间
- Prompt 字数
- 是否使用推荐 Prompt
- 是否使用随机灵感

### 6.8 积分换算系统

**描述**: 根据生成模式和输入参数组合计算本次生成所需积分，兼顾用户可理解性与平台成本控制。

**MVP 换算原则**:
- 普通生成基础消耗为 1 积分
- 高清生成基础消耗为 2 积分
- 超精细生成基础消耗为 3 积分
- 参考图会增加额外计算成本，应增加积分消耗
- 特定比例、复杂模板或高阶生成参数可增加额外积分消耗
- Prompt 字数本身不单独收费，但超出系统建议长度时触发提示或限制

**建议的 MVP 计费规则**:

| 条件 | 取值 | 积分变化 |
|---|---|---|
| 生成质量 | `standard` | `1` |
| 生成质量 | `hd` | `2` |
| 生成质量 | `ultra` | `3` |
| 比例 | 所有 MVP 比例 | `+0` |
| 风格 | `style_cinematic` | `+1` |
| 风格 | 其他基础风格 | `+0` |
| 模板 | `tpl_xiaohongshu_cover` / `tpl_video_cover` / `tpl_character_sheet` | `+1` |
| 模板 | 其他基础模板 | `+0` |
| 参考图数量 | `0` / `1` / `2` / `3` | `+0` / `+1` / `+2` / `+3` |
| Prompt 长度 | `1-300` 字 | `+0` |

**最终积分消耗计算公式（MVP）**:

```text
final_points =
  quality_points
  + style_extra_points
  + template_extra_points
  + reference_image_extra_points
```

**最终积分消耗示例枚举**:

| final_points_case_id | 场景 | 计算结果 |
|---|---|---|
| `case_basic_avatar` | 普通生成 + 盛唐 + OC头像 + 无参考图 | `1` |

### 6.9 生成流程与加载态

### 6.16 失败兜底机制

**描述**: 由于 AI 生成天然存在失败和不稳定情况，系统必须提供可预期的失败处理策略。

| 场景 | 处理策略 |
|---|---|
| 生成失败 | 自动退款积分 |
| 超时 | 自动重试 |
| 内容违规 | 返回安全提示，不出图 |
| 模型异常 | 降级到备用模型或备用配置 |

### 6.17 内容安全策略

**描述**: 内容审核是平台核心安全能力，不能只做 Prompt 审核，必须覆盖生成前后全链路。

**Prompt 审核范围**:
- 色情
- 政治
- 真人明星
- 未成年人敏感内容
- 暴力

**图片审核策略**:
- 生成后审核
- 审核不通过的图片不对用户直接展示或下载
- 需保留违规原因与处理结果

### 6.18 风控与限流策略

| 类型 | 限制 |
|---|---|
| 游客 | 禁止直接生成 |
| 新用户 | 每日 20 次 |
| IP 限流 | 每分钟 5 次 |
| Prompt 重复 | 触发防刷策略 |

### 6.19 缓存策略

**描述**: 为降低 AI 图片生成成本，系统应支持相同参数复用。

**规则**:
- 相同 Prompt + 相同参数组合，可命中缓存复用已有结果
- 命中缓存时，不再触发完整生成链路
- 缓存命中策略需兼顾用户体验、版权风险与结果时效性

### 6.23 OpenAI-Compatible 模型配置中心

**描述**: 后台应支持配置多个兼容 OpenAI 接口规范的文生图模型或服务，方便统一调度调用。

**配置目标**:
- 支持多个模型服务并存
- 支持不同服务商的 OpenAI-compatible 接口接入
- 支持按模型区分能力、价格、优先级和状态

**模型配置项（MVP）**:
- `provider_id`
- `provider_name`
- `base_url`
- `api_key_ref`
- `model_name`
- `api_mode`：`openai_compatible`
- `capabilities`：文生图 / 图生图 / 参考图
- `priority`
- `status`：启用 / 停用 / 降级
- `timeout_seconds`
- `qps_limit`
- `cost_level`

**管理能力**:
- 新增模型配置
- 编辑模型配置
- 启用/停用模型
- 设置默认模型
- 配置主模型 / 备用模型

**交互流程**:
1. 管理员进入模型配置中心
2. 新增或编辑 OpenAI-compatible 模型配置
3. 保存后系统校验配置有效性
4. 模型进入可调度列表
5. 生成服务按配置进行调用

**数据需求**:
- 模型配置列表
- 当前默认模型
- 主备模型关系
- 配置变更日志

### 6.24 模型状态监控

**描述**: 后台应提供模型运行状态监控能力，帮助管理员快速发现模型异常、耗时升高或调用失败问题。

**监控维度**:
- 模型在线状态
- 最近调用成功率
- 平均响应时间
- 超时次数
- 失败次数
- 审核拦截率
- 当前排队任务数

**状态枚举（MVP）**:

| status_id | 含义 |
|---|---|
| `healthy` | 正常可用 |
| `degraded` | 可用但性能下降 |
| `unavailable` | 不可用 |
| `maintenance` | 维护中 |

**告警场景**:
- 连续调用失败
- 平均响应时间超阈值
- 超时率异常升高
- 模型被手动停用

**交互流程**:
1. 管理员进入模型监控页
2. 查看各模型当前状态和关键指标
3. 发现异常后可切换默认模型或启用备用模型
4. 系统保留告警和处理记录

**数据需求**:
- 模型状态
- 调用统计指标
- 告警记录
- 切换记录

## 8. 验收标准

- [ ] 用户能够完成一次“登录 -> 输入 Prompt -> 选择风格 -> 发起生成 -> 查看结果 -> 下载图片”的完整流程
- [ ] 首页能够在首屏清晰传达“AI 国风角色生成器”的产品定位
- [ ] 首页展示 Banner、风格展示区和示例角色区，并可引导用户进入生成流程
- [ ] 未登录用户可以直接浏览首页公开内容，无需登录即可查看产品介绍、风格展示和示例角色
- [ ] 新用户首次登录后可获得 10 次免费生成额度
- [ ] 系统能够根据用户输入和所选风格自动完成 Prompt 增强与提交
- [ ] 用户可以在生成前配置比例、风格、模板，并可选上传参考图
- [ ] 系统能够在生成前清晰展示本次所需积分，并按参数组合正确扣减
- [ ] 生成过程中系统能够展示“AI 正在绘制中...”及预计耗时提示
- [ ] 结果页支持查看大图、下载、分享、再次生成
- [ ] 用户可以查看“我的作品”“收藏作品”“最近生成”
- [ ] 当积分不足时，系统能够提示充值并展示预设套餐
- [ ] 用户数据隔离生效，用户不能访问其他用户的作品与账户数据
- [ ] 系统支持“生成 -> 分享 -> 新用户回流 -> 再生成”的增长闭环
- [ ] 新手用户可以通过推荐 Prompt 或一键灵感完成首次生成
- [ ] 生成失败、超时、违规、模型异常时均有明确兜底策略

- [ ] 系统具备基础任务队列状态机与限流防刷能力
- [ ] 管理员能够登录后台查看并维护用户信息
- [ ] 后台支持配置多个 OpenAI-compatible 文生图模型
- [ ] 后台能够监控模型状态、成功率、响应时间和异常情况

## 9. 依赖与风险

| 依赖/风险 | 说明 | 应对措施 |
|---|---|---|
| AI 绘图模型 | 生成质量、稳定性与耗时强依赖外部模型能力 | 在设计阶段明确模型接入协议、超时与失败重试策略 |
| 支付系统 | 积分充值依赖第三方支付能力，需接入微信支付或支付宝 | 在设计阶段明确支付渠道、回调机制、订单状态同步与对账策略 |
| 手机号验证码服务 | 手机注册与登录依赖外部验证码服务 | 在设计阶段补充验证码频率限制、失败重试与风控策略 |
| MinIO 存储 | 图片存储与访问依赖对象存储服务 | 设计阶段明确上传、访问控制、文件命名与清理策略 |
| 积分换算规则仍可调整 | 参考图、模板复杂度、特殊比例的附加积分当前为 MVP 方案 | 在设计阶段确认最终扣费规则，并视需要回写 PRD |
| 内容审核策略复杂 | 仅靠 Prompt 审核不足，图像审核与误杀处理也需设计 | 在设计阶段补齐审核链路、误判申诉与兜底策略 |
| 功能边界仍有待细化 | 当前未明确收藏作品来源、分享落地方式、缓存命中策略细节和多参考图上限 | 在设计阶段补充细化，并视需要回写 PRD |
| 多模型配置复杂 | 多个 OpenAI-compatible 服务的协议细节、稳定性和成本差异可能较大 | 在设计阶段统一抽象配置结构、调用适配层和降级策略 |
| 管理员权限风险 | 后台可查看和修改用户信息，存在敏感数据和越权风险 | 在设计阶段补充后台 RBAC、操作审计和敏感字段脱敏策略 |
